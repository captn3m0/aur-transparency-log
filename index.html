aur-transparency-log

A trustworthy answer to "when did this AUR commit first appear?", so AUR helpers can wait out a cooldown before installing an update.

Why

A cooldown means waiting N days after a release before installing it, so scanners and people can catch malicious updates. Git dates are chosen by whoever pushes, and the AUR only exposes the last change time of the current head. This service records when each head was first seen, with a time Sigstore vouches for, not us.

How it works

  1. Every minute a Cloudflare Worker reads the AUR "modified" feed.
  2. It confirms each new head directly on aur.archlinux.org.
  3. It signs one statement per batch of commits.
  4. Sigstore's timestamp authority timestamps the signature, and Rekor v2 logs it.
  5. The signed bundle is stored; nothing lives in this repository.

A compromised observer can only make commits look newer, never older. At launch the current state of every package was entered the same way.

Query

Ask for the newest commit that already passes your cooldown. Give a Unix time rounded down to the hour, so everyone asking in the same hour shares a cached answer.

before=$(( $(date +%s) / 3600 * 3600 - 7*86400 ))   # 7-day cooldown
curl "https://aur-tl.captnemo.in/v1/pkg/yay?before=$before"

/v1/keyssigning keys with hint and PEM (PEM, JWKS)
/healthzcron age and last error

All endpoints are GET with open CORS. The result's status is ok, too_new (the newest commit is newer than the cutoff: fail the cooldown or roll back via /history) or not_observed. A bad before returns 400 with the rounded value in suggest. Full documentation is in the README.

Verify

Don't trust the API; trust the bundle it points to. A bundle names its signing key by hint, so pick the matching key from /v1/keys, then take the time from the RFC 3161 token, not from the API. A worked example for a real package is in Usage.

curl -sO https://aur-tl.captnemo.in/b/1795649492-6b25f276.sigstore.json
hint=$(jq -r .verificationMaterial.publicKey.hint 1795649492-6b25f276.sigstore.json)
curl -s https://aur-tl.captnemo.in/v1/keys | jq -r --arg h "$hint" '.keys[] | select(.hint == $h) | .pem' > worker.pub
printf %s 'aur/python-transformers' > subject
cosign verify-blob-attestation --key worker.pub \
  --bundle 1795649492-6b25f276.sigstore.json \
  --type https://captnemo.in/aur-transparency-log/aur-published-key/v1 subject

Limits

  • If the feed (about 90 minutes of history) is missed during an outage, packages can be skipped.
  • Deletions are not attested, and only observed heads are, never intermediate commits.
  • No HA guarantees, and no entries before 2026-11-25.
  • Trusted timestamps can be well after the AUR's LastModified, since timestamping is delegated to Sigstore.
  • The signing key is a Worker secret, not an HSM.
  • Rekor v2 has no search: find an entry by the log index in its bundle.
