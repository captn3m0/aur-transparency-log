aur-transparency-log

Trusted publish timestamps for AUR commits, so AUR helpers can enforce dependency cooldowns.

Why

A cooldown means waiting N days after a release before installing it, giving scanners and humans time to catch malicious updates. For the AUR that needs a trustworthy answer to "when did commit X first appear?". Git dates are chosen by the pusher, and the AUR only exposes the last modification time of the current head.

How

Every five minutes a GitHub Actions workflow reads the AUR "modified" feed, confirms each head directly on aur.archlinux.org, and signs one statement listing the new commits. The signature is keyless (GitHub OIDC) and logged in the public Sigstore Rekor log, so the timestamp comes from Sigstore rather than from us. A compromised observer can only make commits look newer, never older. Nothing is stored in the repository.

Verify

Attestations are signed by this workflow identity:

https://github.com/captn3m0/aur-transparency-log/.github/workflows/observe.yml@refs/heads/main
issuer: https://token.actions.githubusercontent.com
predicate: https://captnemo.in/aur-transparency-log/aur-published/v1
printf %s 'aur/yay' > subject
gh attestation verify subject -R captn3m0/aur-transparency-log \
  --predicate-type https://captnemo.in/aur-transparency-log/aur-published/v1

Limits

GitHub cron can be late, and the feed keeps about 90 minutes, so a delayed run may miss packages. Deletions are not attested yet. Only observed heads are attested, never intermediate commits.
