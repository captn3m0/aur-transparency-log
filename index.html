aur-transparency-log

Trusted publish timestamps for AUR commits, so AUR helpers can enforce dependency cooldowns.

Why

A cooldown means not installing a release until it is N days old. Git commit dates are set by whoever pushes, and the AUR only shows when the current head was last modified. This service records when each head was first seen on aur.archlinux.org and signs it. The time comes from Sigstore's timestamp authority, not from this project.

How it works

  1. A Cloudflare Worker reads the AUR modified feed every minute.
  2. It checks each new head against aur.archlinux.org.
  3. It signs one statement per batch of commits.
  4. Sigstore's timestamp authority timestamps the signature and Rekor v2 logs it.
  5. The signed bundle is stored in R2.

A compromised observer can make commits look newer, never older. Packages already in the AUR on 2026-11-25 were entered the same way.

Query

before is a Unix time that must be a multiple of 3600, so all clients in an hour share one cached URL. The call returns the newest commit at or before it.

before=$(( $(date +%s) / 3600 * 3600 - 7*86400 ))   # 7-day cooldown
curl "https://aur-tl.captnemo.in/v1/pkg/yay?before=$before"
EndpointReturns
/v1/pkg/<pkgbase>?before=newest commit at or before the cutoff

/v1/recentlatest attested commits
/v1/keyssigning keys with hint and PEM (PEM, JWKS)
/healthzcron age and last error

All endpoints are GET with open CORS. The result's status is ok, too_new (the newest commit is newer than the cutoff; fail the cooldown or use /history) or not_observed. A bad before returns 400 with the rounded value in suggest. Full documentation is in the README.

Verify

Verify the bundle, not the API. The bundle names its key by hint; pick the matching key from /v1/keys. Take the time from the RFC 3161 token. Usage walks through this for a real package.

curl -sO https://aur-tl.captnemo.in/b/1795649492-6b25f276.sigstore.json
hint=$(jq -r .verificationMaterial.publicKey.hint 1795649492-6b25f276.sigstore.json)
curl -s https://aur-tl.captnemo.in/v1/keys | jq -r --arg h "$hint" '.keys[] | select(.hint == $h) | .pem' > worker.pub
printf %s 'aur/python-transformers' > subject
cosign verify-blob-attestation --key worker.pub \
  --bundle 1795649492-6b25f276.sigstore.json \
  --type https://captnemo.in/aur-transparency-log/aur-published-key/v1 subject

Limits

  • No HA guarantees.
  • No entries before 2026-11-25.
  • The AUR feed only covers about 90 minutes. Packages can be skipped if it is missed during an outage.
  • Only observed heads are attested, not intermediate commits. Deletions are not attested.
  • Timestamps can be well after the AUR's LastModified, because timestamping is delegated to Sigstore.
  • The signing key is a Worker secret, not an HSM.
  • Rekor v2 has no search. Find an entry by the log index in its bundle.
