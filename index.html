aur-transparency-log

Trusted publish timestamps for AUR commits, so AUR helpers can enforce dependency cooldowns.

Why

A cooldown means waiting N days after a release before installing it, giving scanners and humans time to catch malicious updates. For the AUR that needs a trustworthy answer to "when did commit X first appear?". Git dates are chosen by the pusher, and the AUR only exposes the last modification time of the current head.

How

Every minute a Cloudflare Worker reads the AUR "modified" feed, confirms each head directly on aur.archlinux.org, and signs one statement listing the new commits. Each batch gets an RFC 3161 timestamp from Sigstore's timestamp authority and an entry in the public Rekor v2 log, so the time comes from Sigstore rather than from us. A compromised observer can only make commits look newer, never older. Bundles live in object storage, and nothing is stored in this repository.

Query

Ask for the newest commit that already passes your cooldown by giving a Unix time rounded down to the hour, so answers cache well:

curl 'https://aur-tl.captnemo.in/v1/pkg/python-transformers?before=4102444800'

Other endpoints: /v1/pkg/<pkgbase>/commit/<sha>, /history and /v1/batch.

Verify

Download the returned bundle, then check its signature, timestamp and log entry. Take the time from the timestamp token, never from the API, and confirm the commit appears in the statement.

printf %s 'aur/python-transformers' > subject
cosign verify-blob-attestation --key worker-1.pub --bundle bundle.json \
  --type https://captnemo.in/aur-transparency-log/aur-published-key/v1 subject

Key worker-1 (SHA-256 of DER 6cb2c44d…12fe), also published as a JWKS with a discovery document; issuer https://captnemo.in/aur-transparency-log.

Limits

The feed keeps about 90 minutes, so a long outage can miss packages. Rekor v2 has no search, so find an entry by the log index in its bundle. Deletions are not attested yet, and only observed heads are attested, never intermediate commits. History starts at launch.
